02 — 조치 A

파일 통합: 점검 하나, 출력 하나

실행에 필요한 파일을 4개에서 2개로 줄였다. 역할 경계를 "점검"과 "출력" 두 개로만 나눈다.

이전 — 4파일 
career_analysis_comprehensive.py
        │
        ├─ import analysis_response
        ├─ import hallucination_guard
        └─ import star_quality ─────┐
                                    └─ import
                                       hallucination_guard
이후 — 2파일 
career_analysis_comprehensive.py  (출력)
        │
        └─ import hallucination_guard  (점검)

# analysis_response  → 출력 파일로 흡수
# star_quality       → 점검 파일로 흡수

병합 전 이름 충돌 전수 대조

두 파일을 그냥 이어붙이면 같은 이름이 겹칠 때 나중 정의가 앞 정의를 조용히 덮어쓴다. 병합 전에 최상위 이름을 전부 대조했다.

겹친 이름두 값이 동일한가처리
_METRIC_RE 문자 단위로 동일 확인 중복 정의 제거, 점검 A절 정의를 B절이 재사용
_STAR_SLOTS 둘 다 ("S","T","A","R") 중복 정의 제거
(그 외) — 충돌 없음. analysis_response 도 겹치는 이름 없음

만약 두 _METRIC_RE 가 미묘하게 달랐다면, 합친 파일에서는 STAR 사전판정과 품질채점이 서로 다른 기준으로 수치를 인식하는 조용한 버그가 됐을 것이다. 값이 같음을 확인했기에 안전하게 하나로 합쳤고, 갈라지지 않도록 주석으로 못 박았다. 

# 참고: _METRIC_RE·_STAR_SLOTS 는 위 A 절에서 이미 정의된 동일 값을
#       그대로 재사용한다 (중복 정의 금지 — 값이 갈라지면 A/B 두 검사가
#       서로 다른 기준으로 판정하는 조용한 버그가 된다).

star_quality.py 안에 있던 자기참조 import (from hallucination_guard import ...) 2곳도 함께 제거했다.

03 — 조치 B

v2.0 형식 복원 3건

v2.0 원본을 기준 형식으로 삼아 대조한 결과, 세 군데가 벗어나 있었다. 기능이 아니라 호출 규약과 코드 형태의 문제다.

F-1Entry

__main__ 블록을 main() 단순 호출로 복원

v3.1 은 stdin·환경변수를 블록 안에서 읽어 인자로 넘기는 형태였다. v2.0 형식인 main() 무인자 호출로 되돌렸다.

v3.1 (이전) 
if __name__ == "__main__":
    _lines = [l.rstrip("\n") for l in sys.stdin] \
        if not sys.stdin.isatty() else []
    main(_lines, os.environ.get("USER_SCHOOL", ""),
         os.environ.get("USER_DEPARTMENT", ""))
복원 — v2.0 형식 
if __name__ == "__main__":
    main()
F-2Envelope

main() 마지막 envelope 블록과 계약 주석 복원

v2.0 의 isinstance 분기와 API Endpoint 계약 주석을 그대로 되살렸다. step 3 의 조기 리턴은 유지되므로 이중 안전망이 된다. 

# ── stdout: 최종 출력을 공통 envelope 형식으로 통일 ──────────────────
# API Endpoint 계약(§3.3 [1]): analyzer main() 은 envelope 를 반환한다.
#   { "status": "success", "vector": [...], "result": { ...payload... } }
# 규약: result(payload) 안에는 status·vector 를 넣지 않는다 (§3.6 #25·#26).
#       vector 는 별도 필드로만, status 는 envelope 최상위로만 나간다.
if not isinstance(result, dict) or result.get("status") == "error":
    resp = ErrorResponse(
        message=(result.get("message", "분석에 실패했습니다.")
                 if isinstance(result, dict) else "분석에 실패했습니다."),
    )
else:
    payload = {k: v for k, v in result.items() if k not in ("status", "vector")}
    resp = VectorSuccessResponse(result=payload, vector=vector)

print(resp.model_dump_json(indent=2, exclude_none=True))
return resp

payload 필터만은 v2.0 의 if k != "status" 대신 not in ("status", "vector") 를 유지했다 — 바로 위 v2.0 주석이 "result 안에는 status·vector 를 넣지 않는다"라고 명시하므로 이쪽이 주석을 정확히 구현한 것이다. v2.0 은 주석과 코드가 어긋나 있었고, result 에 vector 키가 애초에 없어 실무상 결과는 동일했다.

F-3Import

import sys 를 main() 본문 최상단으로

v2.0 과 동일하게 함수 안에 두었다.

04 — 부수 발견

v2.0 의 main() 은 CLI 로 실행된 적이 없다

F-1 을 복원하며 확인한 사실이다. v2.0 원본의 시그니처는 세 인자가 전부 필수였다. 

# v2.0 원본
def main(user_input: list[str], school: str, department: str):
    ...

if __name__ == "__main__":
    main()   # ← 인자 0개 → TypeError

즉 python3 career_analysis_comprehensive.py 로 실행하면 그 자리에서 TypeError 가 났다. 이 줄은 형식상 존재했을 뿐 한 번도 동작한 적 없는 죽은 경로다. 실제 사용은 전부 main(user_input, school, department) 직접 호출이었기 때문에 드러나지 않았다.

판단

형식을 100% 복원하면 이 버그도 함께 복원된다. 그래서 호출 형식(main())은 v2.0 그대로 두되, 인자가 생략되면 main() 내부에서 stdin·환경변수로부터 받아오도록 했다. 형식은 지키고 죽은 경로는 살렸다. 

def main(user_input: list[str] | None = None, school: str = "", department: str = ""):
    import sys
    ...
    if user_input is None:          # ← CLI 실행 시에만 진입
        user_input = [l.rstrip("\n") for l in sys.stdin] \
            if not sys.stdin.isatty() else []
        school = school or os.environ.get("USER_SCHOOL", "")
        department = department or os.environ.get("USER_DEPARTMENT", "")
호출 경로형태동작
백엔드 · Colab main(user_input, school, department) 기존과 완전히 동일 — 변화 없음
CLI main() stdin·환경변수에서 입력을 받아 실제로 동작 (v2.0 에서는 TypeError)

06 — 결과

정리

기능은 하나도 바뀌지 않았다. 환각 가드도, STAR 품질 채점도, 출력 스키마도 그대로다. 바뀐 것은 파일이 놓이는 방식과 main() 의 호출 형태뿐이다.

얻은 것은 두 가지다. 첫째, Colab 반입 시 지켜야 할 파일 경계가 3개에서 1개로 줄어 S-1·S-2 유형의 사고가 구조적으로 어려워졌다. 둘째, v2.0 부터 존재했지만 한 번도 동작하지 않던 CLI 실행 경로가 실제로 쓸 수 있게 됐다.

Colab 반입 절차

# 파일 2개를 업로드하거나, 셀 2개로 나눠 작성
hallucination_guard.py              # 점검
career_analysis_comprehensive.py    # 출력
